# Inkvolt Print

Inkvolt Print (formerly PrintDesk) is a lean Windows app for network printers (and lists any other printer set up in Windows, USB included), replacing HP Smart. Made for HP printers, it also
works with Canon, Epson, Brother and any other IPP Everywhere / AirPrint / Mopria printer (status, ink or toner, scanning, copying,
printing), reads status and toner over SNMP from network printers that speak none of those, and scans through Windows (WIA), or a scanner's own 64-bit TWAIN driver, with scanners that have no eSCL. No account, no cloud, no telemetry, no background services; a driver is downloaded only when you press *Get the driver*, and only the maker's own, its signature checked.

| Feature | How |
|---|---|
| Find printers | Windows' own mDNS/WSD discovery (`DeviceWatcher`): DNS-SD `_ipp`/`_ipps`/`_uscan`/`_uscans` services joined to Windows association endpoints by printer UUID; a service without a `UUID` TXT key joins its host's other services (`Core/Discovery/DnssdJoin`); a printer publishing no UUID at all is added by address. Any brand: nothing filters on HP. The IPP URL comes from the `rp` TXT key and port (IPPS for `_ipps`), the eSCL root from `rs`. Remembered printers connect at startup without waiting for discovery. **Add a printer…** (sidebar, and the empty list's button) for the rest (below). Identity by UUID: a remembered printer whose address now answers with other UUIDs (DHCP gave it to another device) shows "A different device answers at this address" with Fix it… and **This is my printer…** (accepts that device's UUID for the printer, after a repair or reset gave it a new one), never that device's status, supplies or alerts; its connection is closed and the scanner, copy and settings let go of it, so no scan (a jump-list preset included) reaches it. The device is asked who it is on each connect, on each tray background check, when the window comes back from the tray, and every 30 s while connected, before the status is read (one small read: LEDM product config, CDM identity, IPP `printer-uuid` or eSCL capabilities). An address announced by mDNS replaces the one in use when it answers with the printer's UUID; when it can't tell (no answer, or no UUID) the address in use is kept only while it still answers as the same model, so a typed address that works isn't swapped for one that doesn't (`PrinterId.Identify`, `ShouldMove`). |
| Printers set up in Windows | Every real printer Windows has a queue for that discovery doesn't already show (USB, WSD, an older network printer on a TCP/IP or IPP port, one shared from another PC, any brand) is listed too, from the spooler (read only, as the user, every 30 s: the names with `EnumPrinters` level 4, which reads the registry, then each queue's details with `GetPrinter` level 2 at the same time, 5 s each at most, so a print server that's off holds up only its own queue, and a call that hangs isn't started again while it runs; `Core/Queues/QueueKinds`, `TimedCalls`): Print a PDF, Print photos and the print queue card work through its queue. Its status is what Windows and the driver report (`PRINTER_STATUS_*` bits, read every 5 s, in plain words: ready, printing, paused, offline, Use Printer Offline, paper out or jammed, door open, toner or ink low or out as the driver sets them; `SpoolerStatus`), and the status card says so: less than a network printer gives, no ink or toner levels. A WSD or USB printer Windows no longer sees (its `SWD\DAFWSDProvider` or `USBPRINT` device node isn't present, though the spooler still says ready) shows *Not connected* (asked with the 30 s list, only for USB and WSD queues no network printer claims). A queue Windows can't read now isn't taken for removed: only `ERROR_INVALID_PRINTER_NAME` is; a printer shared from a PC that's off reads *Can't reach the PC sharing it*, a spooler that doesn't answer (or answers nothing within 5 s) *Windows isn't answering*, access denied *Status not available*. A queue renamed in Windows is read again at once and keeps the selection (and stays hidden if it was). Queues added, removed or renamed in Windows are read again within a second or so, not at the next 30 s read: the spooler's change notices (`FindFirstPrinterChangeNotification` on the local print server, as the user, asked for queues added and deleted and for their name, port and driver fields, so a status changing while printing isn't one; a burst read once after 0.75 s of quiet, 3 s at most; `Windows/Printing/SpoolerChanges`, `Core/Queues/QueueChanges`); `inkvoltprint queues --watch` shows them. Checked on this PC: a queue added on a file port, renamed and removed gave one notice each. Network queues (TCP/IP, WSD, IPP) show once discovery's first sweep is done (45 s at most), so a printer discovery finds doesn't flash up as its queue first. Virtual printers are left out (Print to PDF, XPS Document Writer, OneNote, fax, "Send To", PDF writers, print to file, remote-desktop redirected printers, Windows 11 virtual print queues). A queue a network printer here already stands for (its device container, the address in its port, the queue Inkvolt Print made for it, or an unambiguous name, as Inkvolt PDF matches them) isn't listed twice, and when discovery finds the printer later the queue's entry gives way to it. *Remove* hides a queue printer while Windows has that queue. `inkvoltprint queues` lists what the app makes of each queue (read only), and what each route below answers. **Levels from the printer through Windows (IPP over USB):** a queue on Windows' *Microsoft IPP Class Driver* (an IPP-over-USB printer, USB printer class protocol 4, which Windows sets up on that driver and carries IPP to over USB itself; or an IPP or WSD network one) is asked through `Windows.Devices.Printers.IppPrintDevice` (Windows 11 22H2, build 22621+; as the user, no capability or administrator; `IsIppPrinter`, then `GetPrinterAttributesAsBuffer`): a read-only Get-Printer-Attributes for state, reasons, alerts and the `marker-*` lists only (no UUID, name, URI or serial), read with the network printers' IPP mapping (`IppClient.ToStatus` / `ToConsumables`; `Core/Queues/IppQueueReading`, `Windows/Printing/IppQueueDevice`). That is the only documented app-level path to an IPP-over-USB printer on Windows: the app never opens the USB device (no libusb, no driver swap), and a USB printer on a maker's driver is not an IPP queue, so this route has nothing for it (its driver is asked instead, below), and one with no driver at all, such as a host-based LaserJet P1006, has nothing to ask. `DeviceQueueStatusSource` (Core) puts it beside Windows' status: each call off the UI thread and cut off at 8 s, read every 30 s while it answers and every 5 minutes while it has nothing; a printer's IPP state leads unless Windows holds the jobs or can't reach it (as with SNMP below); the supplies card says where the levels came from (*From the printer over USB*), and a queue printer that answers with no levels by any route shows *Ink or toner: Not reported by this printer*. Not used for queues read over SNMP. Tested in `QueueDeviceTests` (the IPP fixture as Windows hands it over, with and without its group tag; cut short, too big, garbage, wrong types; a reader that hangs or throws; no identifiers asked). **Levels from the driver (bidi):** a queue with neither of those answering, on a maker's driver, is asked next over Windows' bidirectional printing (`IBidiSpl2.SendRecvXMLString`, CLSID `BidiSpl`; `BIDI_ACCESS_USER`, no administrator; `Windows/Printing/BidiQueueDevice`, `Core/Queues/BidiQueueReading`): two `Get` requests, `\Printer.Consumables` and `\Printer.Status.Summary`, never a `Set`, nothing under `\Printer.DeviceInfo` (it holds the IEEE 1284 id), so no serial or device id can reach a log, `state.json` or a recording; only the error code is logged. Most drivers answer `<Error>13005</Error>` (`ERROR_BIDI_SCHEMA_NOT_SUPPORTED`) or fail the call: *Not reported by this printer*, asked again in 5 minutes. The reply comes from third-party code, so it's read strictly: no DTD, 256 KB at most, 32 supplies, only `Get/Query/Schema` values with the schema's names and types (`:Level` must be a `BIDI_INT` from 0 to 100, otherwise unknown); anything ill formed makes that reply count for nothing; words from the driver must be plain ones, and a problem's words are always the app's (an allowlist of the schema's `StateReason`s). The schema has no low mark, so 10% or less reads low. Windows' status keeps the headline, and a problem it already says isn't said twice. Calls run off the UI thread through `TimedCalls` (7 s, one per printer, a hung driver holds up only its own), and the IPP class driver isn't asked (route 1 has it). The supplies card says *From its driver*. Demo: *Demo USB laser* (`--demo --printer 6 --snapshot x.png`). `inkvoltprint queues --bidi` asks every queue's driver, those the app skips too; Windows' own queues answer 13005 at once (Print to PDF fails with `ERROR_NOT_SUPPORTED`). Tested in `QueueBidiTests` (handwritten replies, Windows' real unsupported reply, entity bomb and external entity, cut short, huge, too deep, wrong types, a hanging driver, the order of the routes). |
| USB printers that need their driver | A USB printer Windows enumerated but can't print to is listed under the printers as *Plugged in, needs its driver* (`Core/Queues/NeedsDriver`, read with the queue list every 30 s and at once when a `USBPRINT` node comes or goes: a PnP watcher). The rule: a present `USBPRINT\…` node bound only to Microsoft's placeholder (*Generic printer device*, `prnms013.inf`, `MS_GENERICPRINT`) or with a driver problem code (1, 18, 28, 31), or a printer-class USB device (`USB\Class_07`) with no driver and no `USBPRINT` node, and no queue on its port (from its `Device Parameters\PortName`) or in its device container. With a real driver (bound, or a spooler driver matching its hardware id or model, `EnumPrinterDrivers` level 6) and still no queue it reads *Driver installed, not set up*: *Set it up* makes the queue on that port with that driver (`AddPrinter` as the user; access denied: says an administrator is needed and opens Windows' Add printer). Its page says what's wrong in plain words and what to do: the maker's driver page (HP and Samsung `support.hp.com/drivers`, Brother, Lexmark, Xerox; else a web search for "<model> driver"), plug in and switch on, install; also Windows Update's optional updates and Settings › Printers & scanners; Windows protected print mode (`HKLM\SOFTWARE\Policies\Microsoft\Windows NT\Printers\WPP`, `WindowsProtectedPrintMode`) only when it's on. Its name comes from the friendly name or the IEEE 1284 MFG+MDL in its ids (`USBPRINT\Hewlett-PackardHP_LaserJet_P1006` → *HP LaserJet P1006*; `PrinterNames`). Reading is read only, no admin; *Get the driver* (row below) is the one thing that downloads or installs, on the user's clicks. The instance id (the USB one ends in the printer's serial number) is used only to read the port: never kept, logged, recorded or shown. `inkvoltprint queues [--unplugged]` lists them as *needs its driver*, `status --all` adds a note for each, Report a problem a line. Demo mode has a made-up *Demo USB laser (no driver)* (`--demo --needs-driver --snapshot x.png`). Found on a real HP LaserJet P1006 (host-based, 2010): Windows Update has no driver for it. |
| USB scanners that need their driver | A USB scanner (or an all-in-one's scanner part) Windows enumerated with no working driver is listed the same way, under the printers and in the Scan tab (a line with *Get the driver*), as *Plugged in, needs its driver* (`Core/Queues/UsbScanners`, `NeedsDriver.Find`; read with the queue list every 30 s, and at once through the PnP watcher, which also watches the USB devices of the scanner makers' vendor ids). The rule: a present `USB\VID_…` device with a driver problem (1, 18, 28, 31) or no driver bound, not of the printer class, that is of the still-image class (`USB\Class_06`), or is from a scanner maker (Epson 04B8, Canon 04A9, HP 03F0, Brother 04F9, PFU/Fujitsu 04C5, Plustek 07B3, Avision 0638, Visioneer 04A7, Kodak 040A, Lexmark 043D) and its bus-reported name or ids say scanner or all-in-one (*Perfection*, *ScanJet*, *LiDE*, *ADS-*, *MFP*…; most scanners report a vendor class, `USB\Class_FF`); never a phone, camera, webcam or other device by its words (Samsung and HP make those too). An all-in-one's scanner part is listed when its printer part prints (an Epson ET on Windows' class driver, the usual case), and not when its printer part is listed as needing its driver too (one entry a device). The still-image class alone counts only with a name that says scanner, or from a scanner maker with a name that isn't a camera's (*EOS*, *PowerShot*, *Coolpix*…): that class is mostly cameras and phones. Its name is the bus-reported one (`DEVPKEY_Device_BusReportedDeviceDesc`: *Epson Perfection V19*), its id its vendor and product ids (`usb-needs-driver:scanner-04b8-013c`): never the instance id, which ends in its serial. `inkvoltprint scanners --needs-driver` lists them. Found on a real Epson Perfection V19 (code 28, `USB\Class_FF`, no class, not in WIA) on this ARM64 PC. Demo mode has a made-up *Epson Demo Scanner (no driver)*. |
| Get the driver | On the page of a printer or scanner that needs its driver, from a maker Inkvolt Print looks up (Epson, Canon, HP, Brother and PFU; `Core/Drivers`): **Get the driver** finds the maker's own download for that model and this PC, downloads it and checks it, shows what it found (title, version, size, signer), and runs it only on **Install**. Epson: epson.com's product search (`/search/autocomplete/SearchBox`, JSON) gives the model's support page (its name the model's words, never a variant such as *V19 II* or a refurbished listing), and that page filtered for this Windows (`?review-filter=Windows 11` or `Windows 10 64-bit`, what its OS menu and GO do) lists the downloads; the first scanner (or printer) driver Epson lists for this Windows is chosen, never a combo package; on ARM64 the first that says it is for ARM ("ARM", "Arm64", "Windows on Arm", any case), on x64 the first that isn't for ARM only; else *Epson has no driver for it that runs on this PC's ARM processor* (`EpsonDrivers`). The others the same way, each from its own site (`DriverPages` holds what they share: model words, the product that is the model, ARM, the offer and its safe file name): **Canon** from Canon's Asia site (asia.canon; Canon USA's and Europe's sites refuse programs): its model suggestions, the driver list for `Windows 11` or `Windows 10 (x64)`, the file's page and its link on `pdisp01.c-wss.com` (sent on to `gdlp01.c-wss.com`); MP Drivers or Printer Driver for a printer, Scanner Driver for a scanner, else the Full Driver & Software Package; models Canon sells only outside Asia aren't there (`CanonDrivers`). **HP** from support.hp.com's own services: the product search (`typeahead`), the systems list (`wcc-services/swd-v2/osVersionData`, *Windows 11*, *Windows 11 on ARM (64-bit)*, *Windows 10 (64-bit)*) and the driver list (`driverDetails`, a JSON post naming only the product and the system, never posted again on a redirect); a printer gets HP's offline full or basic installer first, a scanner HP's scan driver (basic first), never firmware, a .zip or a Microsoft Store link; files on `ftp.hp.com` (`HpDrivers`). **Brother** from support.brother.com: its product search opens the model's page (product code; the model's own name, its *(XL)* aside), the download list for Windows 11 (`os=10068`) or 10 64-bit (`10013`), the chosen download's page past the licence names the file on `download.brother.com`; the kind's own driver, else the Full Driver & Software Package (`BrotherDrivers`). **PFU** (fi and SP series, a Fujitsu vendor id): www.pfu.ricoh.com's list of models and the model's page, whose JSON lists PaperStream IP on `origin.pfultd.com`: TWAIN x64 on x64, its ARM build on ARM64, never the 32-bit TWAIN driver or ISIS (no source Inkvolt Print reads); ScanSnap models have no page there (their software comes through ScanSnap's account site), so none is found (`PfuDrivers`). On ARM64 each site's list for ARM is asked: HP's *Windows 11 on ARM (64-bit)*; Brother, Canon and PFU have no ARM system, so their Windows 11 list, where an ARM build would be; on x64 a page listing only ARM builds is *not found*, never *no ARM driver*. **Licences**: Brother's EULA (its download's page), Canon's disclaimer (the file's page) and PFU's licence (the download's own page, its "more" link, which names PaperStream IP's END-USER LICENSE AGREEMENT) are accepted before the download, so *Get the driver* stops at what it found with *Read Brother's licence* and **Accept and download** (the click accepts it; the command line asks, or `--yes`), and a Store copy opens that page, where it is accepted, instead of the file (`DriverOffer.Licence`; `--demo --needs-driver scanner --get-driver --driver-licence --snapshot x.png`). Signers: *Canon Inc.*, *HP Inc.* (or *Hewlett-Packard Company*), *Brother Industries, Ltd.*, *PFU Limited* (read from real installers). The download: https only, from Epson's hosts only (`ftp.epson.com`, `download.epson.com`, `download*.ebz.epson.net`), each redirect checked against the same list (5 at most), no cookies, 500 MB and 15 minutes at most, the server's length checked first and a file cut short refused (`BoundedHttp`), into a folder of its own under `%LOCALAPPDATA%\InkvoltPrint\Driver downloads`. Kept only when it is a Windows program and its Authenticode signature is valid, chains to a root Windows trusts (revocation checked; `WinVerifyTrust`) and is signed by Epson (*Epson America, Inc.*, *Seiko Epson Corporation*, *Epson Europe B.V.*); otherwise it is deleted and the page says why in words. **Install** checks it again with the file held open, runs it (the installer asks for an administrator itself), waits for it and for every process it starts, followed by process id and start time (Windows reuses ids; a self-extractor exits as soon as its setup runs; 45 minutes at most, its folder kept and swept at a later start-up if something still runs), deletes it, then asks Windows whether it has the device (Windows refusing to start it, SmartScreen, an antivirus or a policy, is said in words): if not, Windows is asked to look again as the user (`CM_Reenumerate_DevNode`), else with one elevated `pnputil /scan-devices`, and failing that the page says to unplug it and plug it back in. A scanner counts once it is plugged in with a working driver and WIA lists one of its model; it is then selected with its Scan tab open. A printer counts once it is plugged in with a real driver or a queue. An unplugged device (as an installer may ask) is still waited for, never found (`DeviceState`). Nothing found: the maker's page for the model (or its support site) and Windows Update's optional updates, as before. `inkvoltprint scanners --needs-driver --get-driver [--yes] [--model "Epson Perfection V19"]` does the same from the command line, asking before it runs anything unless `--yes`. Demo mode's made-up scanner gets a made-up find and downloads nothing (`--demo --needs-driver scanner --get-driver --snapshot x.png`). **A Store (packaged) copy downloads and runs nothing**: *Get the driver* finds the download and shows its title, version and size, **Download it from Epson** (or the other maker) opens the maker's own link in the browser, and the page watches for the device (WIA for a scanner) and says *Found it*, with **Look again** (Windows asked to look as the user, never elevated); unpackaged copies and a sideloading package built with `-IncludeDriverInstall` do it for you (`print/packaging/README.md`, "Get the driver and the Store": Store policy 10.1.5). Downloads left behind are swept at start-up (folders not touched for an hour). Checked on this ARM64 PC: the V19's lookup, download, signature and signer (`--model`, not run); Canon's, HP's, Brother's and PFU's lookups run live once against their sites (a LiDE 400 and G3010, an M234dw, an HL-L2350DW and ADS-1200, an fi-8170, x64 and ARM64) and one installer of each downloaded for its signer; never with their devices plugged in. **Never run here**: the installer through the app, the rescans, the WIA check after them. |
| Set up in Windows | One click: pairs the printer's IPP association endpoint, exactly like Settings → *Add device*. Windows creates an IPP Class Driver queue (and a WIA scanner from the eSCL endpoint). No admin prompt. |
| Scanners through Windows (WIA) | For scanners without eSCL (USB, WSD-Scan, driver-only): Windows Image Acquisition through the scripting library every Windows has (`wiaaut.dll`, `WIA.DeviceManager`), late bound (no package, no interop assembly), on background STA threads (one for the list, one per scanner), as the user (no elevation, also in the packaged copy). It uses the WIA 1.0 device and item properties Windows gives every driver (IDs checked against `wiadef.h`); a WIA 2.0 driver through WIA 2.0's own interface instead (`WindowsWia2`: its glass and feeder items, progress per page, Cancel stopping a page): glass and feeder from *Document Handling Capabilities* (feeder both sides when the driver offers duplex: front first, all pages per job), their sizes from the bed and sheet-feed sizes, color, grey and black and white (the threshold type, 1 bit) from *Data Type*, resolutions from the driver's list or range; a scan sets source, data type and depth, resolution and the area in pixels (within the driver's limits), and takes JPEG from the driver when it offers it, else BMP turned into JPEG by WIA's own `ImageProcess`. A feeder job takes a page per transfer until the driver says `WIA_ERROR_PAPER_EMPTY` (at the start: "Load the pages into the document feeder first"). So a driver can't scan the glass over and over: the feeder setting is read back and a driver that didn't take it scans nothing and says so; before each sheet the feeder's status is read and the job ends when the driver can tell paper is there and says none is ready; a page byte for byte the one before ends the job (a driver sending the glass again); at most 500 pages. Jams, an open cover, lamp off, busy, warming up, offline, locked, access denied and a restarted WIA service in plain words; pages scanned before a jam stay. Cancel stops before the next page and a page queued behind another call is never pulled (a page in progress finishes on the scanner; WIA's scripting library can't stop it). **A hung driver is contained**: the list has 20 s, connecting 60 s, a page 5 minutes; a call that runs past its caller's patience holds up only its own scanner, and nothing more is sent to that scanner until it returns (it reads *hasn't finished its last request*), so calls never pile up; after any failure other than one about the paper or the scanner's state (a WIA service restart's RPC errors included) the scanner is connected again on the next call; the COM objects holding a page's image are released as soon as it's read. Pages go into the same Scan tab as eSCL pages: review, crop, straighten, skip blank, OCR PDF, presets (the feeder's *Document Handling Status* tells a preset whether pages are loaded, when the driver can tell), several photos on the glass, separator sheets, and Copy. **Matching** (`Core/Wia/WiaMatch`): a WIA scanner belongs to a printer on the list by the printer's address in the driver's port, the same name (makers' word variants, "series", driver words and a "(1A2B3C)" suffix aside) or the same model number (a hyphenated one kept whole, so ET-2850 isn't WF-2850; a bare number joined to the word before it) with no other maker named, unambiguous only; a second WIA scanner matching the same printer (its USB and its network driver) is listed on its own; it becomes the Scan and Copy tabs of a queue printer or of a network printer that answered without eSCL, is left alone for a printer with eSCL (eSCL is used), and one no printer claims is listed as a **scanner of its own** (Overview and Scan; "Ready to scan" once connected, "Scanner not answering" while it's off, tried again every 30 s; no tray alerts). `inkvoltprint scanners [--caps]` lists them (and reads what each offers; never scans). Logic in `Core/Wia` (`WiaScanner`, `WiaCapabilities`, `WiaMatch`, `FakeWiaSystem`; tested with the fake); COM in `Windows/Scanning/WindowsWia`. |
| Scanners through TWAIN | For scanners whose maker ships a TWAIN driver and no WIA one (film scanners, older flatbeds and document scanners): 64-bit TWAIN sources through the TWAIN 2 manager (`TWAINDSM.dll`, which makers' TWAIN drivers install; Windows doesn't ship it) are listed beside the WIA scanners in one list (`Core/Wia/DriverScanners`, the same `IWiaSystem` the printer list, Scan, Copy and Fleet read): matched to printers by `WiaMatch`'s rules, else listed as a scanner of its own ("A scanner with its maker's TWAIN driver" on its card, *Driver: TWAIN* under About), connected and scanned through the same `WiaScanner` plan, feeder loop, error words and hung-driver rules as WIA, so glass, feeder (both sides), color, grey, black and white, resolution and size come from the source's capabilities and its pages go into the same Scan tab (review, clean up, presets, OCR). The source's own window is never shown; pages come by native transfer (a DIB turned into JPEG). A TWAIN source that is a WIA scanner already listed (the same name or model as any WIA entry, so one all-in-one's USB and WSD entries both count) is left out: its Windows driver is used. Listing TWAIN never holds up or costs the WIA list: WIA's scanners show at once and TWAIN's sources join them when read; the manager is read once, again when WIA's list changes (a device plugged in or out) or after 10 minutes, never while a TWAIN source is in use (a call under way or within a minute); a read takes 20 s at most, and a manager that fails or hangs keeps the sources listed before (each failure logged once). Ids are `twain:` and the source's name, so they never take a WIA one. `inkvoltprint scanners [--caps]` lists them too, marked *(TWAIN driver)*. 32-bit-only sources aren't seen (the 64-bit app can't load them). Demo: `--demo --twain` adds a made-up TWAIN-only document scanner, "Demo DocScan 10" (`--printer 10`). Code shared with Inkvolt PDF's Scan dialog, which lists driver scanners through the same `DriverScanners`: `Windows/Scanning/WindowsTwain`, `Core/Twain` (`FakeTwain` for tests). |
| Status, toner, usage | HP LEDM (`/DevMgmt/*.xml`, URIs from `DiscoveryTree.xml`), IPP `Get-Printer-Attributes` as fallback for non-LEDM printers, SNMP for printers with neither (below). |
| Supply history, days left | Each reading's levels and the printer's page count are kept **on this PC**, one row a day per supply (the day's last reading wins; a reading that lost its level or count keeps what the day knew), in one small tab-separated file per printer under the data folder's `history\` (`Core/History/SupplyHistoryStore`): date, supply name and color, level, state, lifetime page count; no serial number, address, document or user, never sent. Bounded: about three years per printer (1,100 days), 16 supplies, names cut to 64 characters, 64 printers (the file written longest ago goes); waste boxes aren't kept; SNMP's and IPP's −1/−2/−3 are stored as no level. Removing a printer removes its file. The supplies card shows each supply's line, **"About 34 days left · 1,240 pages since this cartridge went in"**, and a **level chart** of the last year (the stored rows as they are: a gap where there was no level, a new line with a dot at a change of cartridge; `Views/SupplyChartView`), or "fills in as days pass" until two days are kept. The low-supply notification names the days left. The method (`SupplyAnalysis`): a change of cartridge is a level 20 points or more above the last known one (a wobble at the threshold isn't); days left is a least-squares line by calendar day through this cartridge's levels in the last 30 days (3 readings over 7 days at least, else "Not enough history for days left yet (about N more days)"; a slope under 0.02 points a day is "steady"; past two years it says "More than two years left"), less the days since the last reading; pages per cartridge come from the lifetime count (LEDM printers only: other interfaces give no count, so no pages figure), so on a color printer a color cartridge's figure counts every page printed while it was in. **Export history…** (Inkvolt Pro, free while the gate is off) saves one CSV across all printers: printer, supply, color, date, level, state, pages printed, the day the cartridge was first seen and the pages on it so far (cells a spreadsheet would run as a formula start with an apostrophe; `SupplyHistoryCsv`). Demo mode makes up a believable year behind each printer's first reading (two or three cartridges, noise, a week away; `DemoSupplyHistory`), kept in memory. |
| Add a printer | A window (`Views/AddPrinterWindow`, `AddPrinterViewModel`) that **searches this PC's network as it opens**, for printers that don't announce themselves: every address of each private IPv4 network the PC is on through an adapter with a gateway (RFC 1918 only: never a public, link-local or VPN carrier range; a network larger than a /22 only around this PC, its /24) asked whether it takes print jobs (TCP 631, 9100, 515; 64 at a time, 0.6 s each), and one SNMP GetNext (v2c and v1, `public`) to each network's broadcast address, replies taken for 2 s (`Core/Discovery/NetworkSearch`: a /24 in about 3 s). Each address that answers is asked what it is as a typed address is (LEDM, CDM, IPP, eSCL, SNMP); only printers are shown, those already listed marked *In your list* with **Show**, the others with **Add**. Printers removed from the list earlier that discovery still sees are offered first (*Removed from your list earlier*). ## Inkvolt suite (with Inkvolt PDF)

Inkvolt Print and Inkvolt PDF (the PDF viewer/organizer, `../pdf` in this repository) are separate apps that share code and install together.
Inkvolt Print stays lean (software rendering, no PDF engine of its own: Windows' `Windows.Data.Pdf` draws PDFs); Inkvolt PDF references `InkvoltPrint.Core` and `InkvoltPrint.Windows`
by project reference for scanning (File › Scan…, Insert from Scanner…) and printer status before printing.

- **Open in Inkvolt PDF**: after a scan is saved as PDF, the status line offers "Open in Inkvolt PDF"; Settings has
  "Open scans in Inkvolt PDF" (open every saved PDF there automatically). Both show only when Inkvolt PDF is installed.
  A running Inkvolt PDF receives the file through its own single-instance pipe.
- Inkvolt PDF's File › "Printer Settings (Inkvolt Print)" opens Inkvolt Print when it is installed.
- Each app finds the other via its MSIX app execution alias (`%LOCALAPPDATA%\Microsoft\WindowsApps\inkvoltpdf.exe` /
  `inkvoltprint.exe`), App Paths (`HKCU\…\App Paths\InkvoltPdf.exe` / `InkvoltPrint.exe`), else the default install folders
  (`%LOCALAPPDATA%\Programs\Inkvolt\<app>`, `%LOCALAPPDATA%\Programs\<app>`): `InkvoltPrint.Windows/Suite/InkvoltApps.cs`,
  paths in `InkvoltPrint.Core/Suite/InkvoltPaths.cs`. A packaged Inkvolt Print's `state.json` lives in its package folder;
  `InkvoltPrinters.Load` reads whichever copy was written last.
- Shared, UI-free pieces in `InkvoltPrint.Core/Suite`: `InkvoltPrinters` (read-only view of `state.json`'s remembered
  printers and queue associations), `QueueMatch` (Windows queue → printer: stored association, device container, address
  in the port, unambiguous name), `PrinterHealth` (ready/sleeping/error/offline, toner, paper problems), `ScanChoices`
  (sources, colors, resolutions, page sizes → `ScanRequest`; Inkvolt Print's Scan tab uses its page sizes).
- **Inkvolt Pro, one key for both apps** (Help › Inkvolt Pro…): a one-time $19 licence, no account, nothing sent. The
  window shows Free or "Pro licensed to NAME", takes a pasted key (a refused key says why in plain words: not an Inkvolt
  Pro key, altered or not pasted whole, made for a newer version, for Inkvolt PDF only), opens the product page (`Pro.BuyUrl`; no checkout yet)
  and removes the licence. The key (`INKVOLT-PRO-` and groups of five letters and digits, signed with our private key:
  `pdf/tools/pro-key/README.md` has the format and the test vector) names the products it covers (`pdf`, `print`, or
  both) and is checked on this PC against the public key in `InkvoltPrint.Core/Suite/ProKeys.cs` (ECDSA P-256), the
  same code for both apps; each app's `Pro` (`InkvoltPrint.Core/Pro.cs`, `InkvoltPdf.Core/Pro.cs`) sits on the suite's
  `ProCheck` for its product. The key lives in **`%LOCALAPPDATA%\Inkvolt\pro-key.txt`**, written and read by both apps
  (`Suite/ProKeyFile`; a Store copy's write lands in its package folder, `Packages\<family>\LocalCache\Local\Inkvolt\`,
  which the other app looks in too, as it does for `state.json`), so a key entered in Inkvolt PDF licenses Inkvolt Print
  and removing it in either app removes it for both; a key from an app's own settings (Inkvolt PDF 1.2.1 kept it there)
  moves into the file on first read, and the settings hold a copy only when the file can't be written. Inkvolt Print's
  Pro features are the roadmap's office ones (supply history export, batch print lists and the command line, fleet
  export, SNMPv3; scanner sharing is free since 2026-11-22); `Pro.Allows(feature)` is their one check, and **the gate is off
  while the apps launch** (`ProCheck.Enforced`, one switch for both; see the roadmap's "Free and Pro"): everything is
  free, a key is still verified and shown. Tested in `ProTests` (the vector against the built-in key, every changed
  character refused, a print-only key refused by the PDF check, the shared file, a packaged copy's redirected file).
  Untried in the Store packages: that one packaged app sees the other's redirected copy, and that a packaged copy
  deleting the file removes it for an unpackaged one (listed under "Not done").
- One installer for both: `install-suite.ps1` at the repository root (`%LOCALAPPDATA%\Programs\Inkvolt\InkvoltPdf` and
  `\InkvoltPrint`, Start Menu folder "Inkvolt", App Paths; `-Uninstall` removes only what it added).
- `InkvoltPrint.exe --unregister` (no window; exit code 0, or 1 when the registry refused) removes what the app itself writes
  to HKCU: the "Open with" ProgIds for PDFs and pictures, their `OpenWithProgids` entries, `Applications\InkvoltPrint.exe`
  and the Start-with-Windows `Run` value, each only when it points at that exe (another copy's entries stay;
  `Core/Suite/ShellRegistration`, tested). It's a GUI exe, so wait for it: `Start-Process -Wait`. Those entries and the
  jump list are written by the installed copy (the installer's folders), or by another unpackaged copy only when they're
  missing or point at an exe that's gone: a second copy in another folder never takes them over (`MayRegister`).

## Design notes (vs. HP Smart's problems)

- One `HttpClient` per printer, per-request timeouts (5 s default; scan pages 3 min). No shared mutable port/scheme/timeout.
- No HTTP→HTTPS retry multiplication, no nested retry loops. Offline printers are retried every 20 s or when mDNS sees them again.
- Self-signed printer certificates are accepted only for that printer's host, never process-wide.
- Admin credentials are only ever sent over HTTPS.
- No sync-over-async, no busy-wait polling, no custom multicast sockets.

- Elevated actions (add printer by IP, HP clean-up) run a constant PowerShell script; every value is passed Base64-encoded and results return as exit codes (no temp files).

- Print photos: never printed on a real printer during development. - Maintenance: **every action is untested on hardware.** Built from public sources (HPLIP's `base/maint.py`, the MIT-licensed

- SNMP: the encoder / decoder was built test-first on bytes written by hand from X.690 and RFC 1157 / RFC 3416 (shortest
  INTEGER and length forms, OIDs, the application types, the v2c exceptions), the client against a made-up agent that answers
  as RFC 1157 and RFC 3416 say (RFC 3416's GetBulk example among the tests), and the Printer MIB mapping against objects written
  from RFC 2790 and RFC 3805. On hardware only read: the M234dw answered the probe and a status read over v2c (`inkvoltprint snmp`;
  idle, one toner at the same level its IPP reports, no alerts), and a wrong community got no answer. It has IPP, so the app
  never asks it over SNMP. Never tried on a printer that speaks only SNMP, on a v1-only agent, with real `prtAlertTable`
  entries (jams, doors, trays: which codes, groups and descriptions makers send), on color supplies and waste boxes, on a
  Standard TCP/IP queue (no such port on the development PC: TCPMON's Xcv `HostAddress` / `SNMPCommunity` were only checked
  to open as the user), or on IPv6. To try: an older office laser or MFP without IPP (added by address), a TCP/IP queue whose
  port is named after the printer, a printer with SNMP switched off or a community other than `public` (the queue's own
  community is used; one added by address takes its own, tried only against the made-up agent), and how a printer reports a jam or an open door.
  Printers that answer IPP get no SNMP even when their IPP has no supply levels. A printer added before this check was
  remembered (SNMP-only printers added with the first SNMP build) isn't read over SNMP until it's added by address again.
  The move from SNMP to HTTP and the identity check were tested only with the made-up agents. SNMP-only printers can't be scanned with,
  and their settings and firmware aren't read. A WSD queue's printer is asked over SNMP as a TCP/IP port's is:
  its port has no address, but its WSD device node (the `DAFWSDProvider` node in the queue's container) has PnP-X's IP address
  (`PKEY_PNPX_IpAddress`, else the host of `PKEY_PNPX_XAddrs`; IPv4 only; `QueueKinds.WsdAddress`), read with the 30 s list
  for the unclaimed WSD queues, only while its node is present (an absent one's address may be another device's now) and only once the device that answers says it is this printer (`QueueKinds.SameDevice`: PnP-X's serial number against prtGeneralSerialNumber, else the model numbers in the PnP-X model name or the queue's name; checked again every minute; a new address read on each list gets a new SNMP source, `WsdQueueStatusSource`); a WSD printer that doesn't answer SNMP is still read through Windows' IPP class driver or its
  driver (`WsdSnmpTests`). On this PC the property was there for one of its two WSD printers (the other's node gave none); no
  WSD printer that answers SNMP was on the network to read, and a printer that changes address keeps the old one until the
  app restarts. SNMPv3 (Pro) was tried only against the made-up agent: never against a printer's agent, nor with agents' other auth or
  privacy protocols (MD5, SHA-1, DES, AES-192/256 are spoken and tried only against the made-up agent and
  vectors from RFC 2202, NIST SP 800-38A and Python's own hashlib and cryptography). Which key extension a printer maker's
  agent uses for AES-192/256 after MD5 or SHA-1 isn't documented anywhere we found: both are tried, so a real printer only
  confirms it.

  "pages loaded" is only what the driver's status bits say (some say ready with no paper, so an Auto preset may try the
