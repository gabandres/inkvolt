# Inkvolt for macOS

Native Swift versions of the Inkvolt apps. Inkvolt PDF for Mac (notarized download, AGPL because of MuPDF) is released
(1.13.0 the latest); Inkvolt Print for Mac (MIT) is in the [Mac App Store](https://apps.apple.com/app/id6827219248)
(1.3.1, build 8, the latest; tags `print-mac-v<version>`). Plan, Mac differences and what's left:
[`docs/PLAN.md`](docs/PLAN.md). A new Mac: [`docs/NEW-MAC.md`](docs/NEW-MAC.md).

Builds need macOS 15 or later with Xcode 16 or later:

```sh
swift test --package-path mac/InkvoltPrintKit
```

PrintCore also builds and tests on Windows (Swift 6.4 from winget `Swift.Toolchain`, plus Visual Studio's C++ ARM64 tools
and Windows SDK):

```powershell
pwsh -NoProfile -File mac/tools/swift-dev.ps1 test --package-path mac/InkvoltPrintKit --build-system native
```

A test that measures time takes its limit through `Timing.limit(_:)` (`Tests/TestTiming`, as Windows' `shared/Testing/Timing.cs`):
the Mac's and the PC's limit, five times longer on CI's busy runner. Work that must end on time (a socket's receive loop, a
connection's state handler) runs on a thread or serial queue of its own, never GCD's global pool, which a busy machine
holds for seconds; `PoolHold` in PrintMacTests' TransportTests holds that pool to prove it. A suite whose tests keep a
core busy for seconds without suspending, with no clock of its own (whole pages of image work, scans of the sources), is
`@Suite(.offThePool)` (`Tests/TestTiming/OffThePool.swift`): swift-testing runs every test on Swift's cooperative pool, one
thread a core, and on CI's 3-core runner three such tests at once stopped every timing test for 1.5 minutes. To see what
blocks that pool, run the tests on the build Mac with `GITHUB_ACTIONS=1 LIBDISPATCH_COOPERATIVE_POOL_STRICT=1` (a pool
narrower than CI's) and `sample` the test process.

App Store builds (team AE6TTXW92K, the Inkvolt mobile team) are signed by Xcode with the team's cloud-managed certificates,
authenticated by the App Store Connect API key in `mac/InkvoltPrint/.env.local` (not in git), so the Mac needs no
certificate in its keychain. Run on the Mac, detached; each upload needs a new build number:

```sh
nohup zsh -l mac/InkvoltPrint/release.sh <build> --upload > ~/build-artifacts/inkvolt-print-mac.log 2>&1 &   # git keeps it not executable
cat ~/build-artifacts/inkvolt-print-mac/status          # RUNNING, then DONE 0 or FAILED <step>
node mac/InkvoltPrint/asc-builds.mjs <build> --wait      # until App Store Connect says the build is VALID
```

`release.sh` archives, exports a signed `.pkg`, runs `pkg-preflight.sh` (App Store signatures, the sandbox and exactly
the App Store entitlements and the one app group, Info.plist keys, icon, privacy manifest, demo fixtures, the release Xcode, no crash or
analytics SDK), then validates and uploads with `altool`. The icon and the menu bar glyph come from
`assets/make-icon.py` (the Windows artwork on a macOS tile).

The listing is `assets/store/listing.json` (texts, URLs, categories, review notes) and the screenshots beside it.
`node mac/InkvoltPrint/asc-listing.mjs apply <build>` sets all of it (and the age rating, the free price, every
territory, the review contact, the build) on the version being prepared; `asc-listing.mjs submit` sends it to App
Review. App Privacy ("Data Not Collected") can only be published on the App Store Connect website. Screenshots: a Debug
build's `--snapshot name:index[:scan|photos|clean|print-photos]` (ScreenCaptureKit, needs Screen Recording permission, given once
in System Settings) in demo mode, then `assets/make-screenshots.py <captures folder>` (its docstring has the commands).

`build.sh` signs with the Apple Development identity that `dev-cert.sh` put in its own keychain (once per Mac: the App
Store Connect API key creates the certificate; the keychain's password goes into `.env.local`), so macOS keeps the app's
Screen Recording and Local Network permissions between builds; without it, builds are ad-hoc signed and asked again.

The `mac` CI workflow (`.github/workflows/mac.yml`, macOS 15, the newest Xcode 26, warnings as errors) has two jobs:
`build` tests InkvoltPrintKit and builds the Xcode project; `pdf` builds MuPDF (cached until `build.sh` changes), tests
InkvoltPdfKit and builds the Inkvolt PDF app.

## Releasing

Only when the owner says. Before each release of either app: a hostile-input review of its changes since the last one,
its fixes reviewed and merged.

**Inkvolt PDF for Mac**, on the Mac from the release clone `~/Repos/inkvolt` (pulled), detached:
1. The bench (`tools/bench/README.md`: `make`, `run`), RESULTS.md committed.
2. A dev build (`build.sh`) and the self-test in English and Spanish (`--self-test <report> --edit --synthetic --quit`,
   `--lang es`, `--strings`). **Turn Sparkle's automatic checks off for the run** (`SUEnableAutomaticChecks` and
   `SUAutomaticallyUpdate` NO in `com.bermudezsystems.InkvoltPdf`, back to YES after): otherwise the dev build updates
   itself to the released version mid-run and the later checks test that one.
3. `WHATS-NEW.md` and `WHATS-NEW.es.md` have a `## <version>` heading; `release-notes/<version>.md` and `.es.md` hold the
   appcast's and the GitHub release's notes.
4. `nohup zsh mac/InkvoltPdf/release.sh <version> --appcast > ~/build-artifacts/inkvolt-pdf-mac/release.log 2>&1 &`
   (sign, notarize, staple, the DMG, the appcast; its status file ends `DONE 0`), then
   `INKVOLT_PUBLISH=yes … release.sh <version> --appcast --publish`: the GitHub release `pdf-mac-v<version>` (not Latest:
   Latest is the Windows app's) and the `appcast` branch.
5. The Homebrew cask in `gabandres/homebrew-inkvolt` (version, sha256; push from a clone of the tap) and the website
   (`Z:\portfolio`: the Mac download's version and size, the Spanish pages too).
6. Check: an installed older version finds the new one in the feed (en, es), and the DMG installs (notarized, accepted).

**Inkvolt Print for Mac**: `release.sh <build> --upload` and `asc-builds.mjs <build> --wait` (above), then
`asc-listing.mjs apply <build>` (What's New from `WHATS-NEW.md`'s `## <version>`; Spanish only when the version has an
es-MX localization in App Store Connect) and `asc-listing.mjs submit`. After Apple approves: the tag
`print-mac-v<version>` on the commit built, and the website.

## Gotchas

- Vision's checks (redaction, OCR, Compare's scans) fail when the Mac is under heavy load (hundreds of other processes):
  rerun them on a quiet Mac before believing a failure.
- CI's macOS runner is slow and its Xcode older: heavy tests skip on `GITHUB_ACTIONS`, and long expressions the Mac
  compiles may need splitting (build with the 150 ms type-check flag, `mac/CLAUDE.md`).
