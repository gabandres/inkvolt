# Inkvolt PDF

Inkvolt PDF (formerly PdfDesk) is a fast PDF viewer and page organizer for Windows on ARM, modeled on PDF-XChange Editor's viewing and
Organize features. Native ARM64 (.NET 10 WPF + MuPDF). Open source under the GNU AGPL v3, by
[Bermudez Systems](https://bermudezsystems.com). Part of the [Inkvolt suite](../README.md) with
[Inkvolt Print](../print/README.md), in the same repository.

## Install

Commands run from this folder (`pdf/`) unless they say otherwise.

```powershell
pwsh -File install.ps1            # builds publish\win-<arch>\InkvoltPdf.exe (ARM64 or x64, for this PC), installs to %LOCALAPPDATA%\Programs\InkvoltPdf
pwsh -File install.ps1 -Uninstall
```

Installs one self-contained native `InkvoltPdf.exe` (no .NET needed), Start Menu and Desktop shortcuts, a PDF document
icon, and "Open with" entries for .pdf/.xps/.oxps/.epub/.cbz/.fb2. To make it the default: Settings › Apps › Default apps ›
Inkvolt PDF. Icons (and the MSIX images) are generated by `python -I assets/make-icon.py`. Publish profiles: `win-arm64`, `win-x64`.

Microsoft Store / MSIX (x64 + ARM64 bundle), from the repository root: `pwsh -File packaging/pack-msix.ps1 -App Pdf`, see
`packaging/README.md` (this folder's).

### Build from source

```powershell
git clone https://github.com/gabandres/inkvolt.git
cd inkvolt/pdf
dotnet build InkvoltPdf.slnx
dotnet test tests/InkvoltPdf.Tests
```

Needs the .NET 10 SDK on Windows 10 (19041) or later, x64 or ARM64. `dotnet build Inkvolt.slnx` at the repository root
builds both apps.

Installing Inkvolt PDF and Inkvolt Print together (one Start Menu folder, each app finding the other): the
[repository README](../README.md#install-both).

## Using it

- **Windows 11 look**: Mica, document tabs in the title bar (Snap Layouts kept), light/dark/system theme (Ctrl+,). The
  command bar stays one row: on a narrow window labels give way to icons, then the rest goes into the "…" menu.
- **Tabs**: next / previous with Ctrl+Tab / Ctrl+Shift+Tab or Ctrl+PgDn / Ctrl+PgUp, Ctrl+Alt+1…9 picks one,
  Ctrl+Shift+T reopens the last closed tab at its page (the last 10). A file opened from Explorer while Inkvolt PDF is
  asking about unsaved changes before closing waits, and keeps the window open for itself. Right-click a tab (or Shift+F10)
  for Close, Close Others, Close Tabs to the Right, Copy Path, Show in Folder and Reopen Closed Tab; middle-click closes it.
  Tabs that would read the same (two documents with the same title, or files of the same name) add the file name or folder
  ("report.pdf · 2026"); the tooltip has the full path.
- **Start page**: open a file, or drop files anywhere; recent files show a first-page preview. **Tools**: twelve cards for the
  main tools (Fill & sign, Edit text & images, Export to Word, Combine, Compare, Reduce file size, Protect, Redact, OCR,
  Organize pages, Batch, Create a PDF: a menu of Office file, web page, images, clipboard, scanner). Each runs its command
  (`MainWindow.StartPage.cs`, the command in the card's `Tag`); one that needs a document first asks for a PDF, opens it and
  then runs. Before any file has been opened, a tip points at the command palette (Ctrl+K) and F1.
- **New PDFs from images**: File › New from Images… (JPEG, PNG, BMP, GIF, TIFF; page size: fit each image, Letter or
  A4) or New from Clipboard (Ctrl+Alt+N: a copied image such as a screenshot, or copied image files). Image files
  dropped on the window ask: a new PDF of them, pages at the end of the open document, or just view them; dropped on
  the thumbnails or the organizer they become pages right there. The result opens as an unsaved "Untitled.pdf".
- **PDF from Office files and web pages** (File › PDF from Office File… / PDF from Web Page…, command palette; File ›
  Open and dropping a .docx, .xlsx, .pptx, .html or .mht do it too): Word, Excel and PowerPoint files (also .doc, .rtf,
  .odt, .xls, .ods, .ppt, .odp and the macro-enabled kinds) are made into PDFs by the Microsoft Office installed on the
  PC (no converter of Inkvolt PDF's own, no service): it opens the file read-only and hidden, with its macros disabled,
  saves it as PDF and closes it without saving. Word and Excel run as a new copy of their own, never the one you work
  in; PowerPoint runs one copy at a time, so it is asked to be closed first. The work runs in a helper process with a
  3-minute limit, and Cancel or the limit ends it and the Office it started (never an Office showing a window, which
  may hold a document you opened meanwhile: that one is left running and you are told). Links aren't updated on open,
  and a file Windows marks as downloaded from the internet asks first, since automation opens it without Protected View. Shown only when Office is installed; a
  file protected with a password is refused (save it as PDF from Office). Web pages: an address, or a saved .html /
  .mht, loads in Microsoft Edge WebView2 (part of Windows) in a private session that keeps no cookies or history, with
  pop-ups, downloads and permission requests blocked, then prints to PDF with the chosen paper (Letter, A4, Legal),
  orientation, margins, background colors and pictures, and optionally the browser's header and footer. The PDF opens
  as a new unsaved tab; the original isn't changed.
- **Reading**: continuous / single / two pages / two pages with cover; a floating pill for page and zoom; Ctrl+wheel or
  touchpad pinch zooms at the pointer, touch screens pinch and pan; fit width / fit page; dark pages for night reading
  (hue-preserving); full screen (F11 or Ctrl+L); go to page (Ctrl+G or Ctrl+Shift+N); **rotate view** (View menu, Ctrl+Shift+Plus / Ctrl+Shift+Minus) turns the pages
  on screen only, per tab, without changing the file (thumbnails, printing and export stay as they are; links,
  selection, fields and comments follow the turn); each file reopens where you left it, zoom and view rotation
  included. Page labels (i, ii, A-1…) show in the
  page pill and under thumbnails and can be typed to jump; a new file opens the way it asks (pane, layout, start page,
  title as the tab name).
- **Split view** (View › Split View: Top and Bottom, or Side by Side): two places of the same document at once, each
  pane with its own page, scroll, zoom, layout and view rotation; drag the bar between them to resize. The active pane
  has an accent frame: page and zoom commands, the page pill, thumbnails and bookmarks move it. Click a pane, or press
  Ctrl+F6 (F6 visits both in its cycle), to switch. The panes share the document, its undo history and the page
  selection: an edit made in one shows in the other at once. The second pane is for reading (hand, text selection,
  snapshot, links, copy); tools that change the document work in the main pane, which becomes active when one is
  picked. The × in the second pane (or Remove Split) closes it. Kept per tab while it is open.
- **Side rail**: Pages (thumbnails), Bookmarks, Search, Comments, Attachments, Layers, Signatures; F4 hides the pane.
- **Bookmarks**: Ctrl+B adds one for the page and spot in view (titled with the selected text, else the page; type
  the title in place, Enter), after the selected bookmark; rename with F2 or a double-click, Del deletes, drag to
  reorder or drop onto another to nest it; right-click for Add Child, Set Destination to Current View, Expand/Collapse
  All. Each change is one undo step (on a signed file it is appended, which signatures allow).
- **Read Aloud** (View menu, Ctrl+Shift+Y): reads from the top of the view, or just the selection, with a Windows voice;
  the sentence and word being read are highlighted and followed. A bar on top: pause, stop, previous/next paragraph,
  voice and speed (0.75×-2×). Stops when the document changes or its tab closes.
- **Forms and Fill & Sign**: fill text fields, check boxes, radios and lists (Tab moves on; AF calculations and formats
  run; values are drawn into the fields' own appearances without NeedAppearances, so pdf.js, poppler and others show
  them formatted, as here); type text or put check marks/crosses anywhere on a page (A, K, X); **Sign** places a handwritten signature or
  initials (drawn with mouse/pen/touch, typed in a script font, or an imported image; up to 3 signatures + initials saved
  on this PC) as a stamp every viewer shows: drag to move, drag the corner to resize, Delete removes it (undoable).
- **Prepare Form** (Edit › Forms › Prepare Form, Ctrl+Alt+F, or the command palette): add and edit form fields. A
  bar over the page picks the field kind (text, check box, radio button, dropdown, list box, signature, push button):
  drag on the page to place one, or click for the kind's usual size (with a radio button selected, the next one joins its
  group). Click a field to select it: drag to move it, drag a handle to resize it, arrow keys nudge it (Shift: 10 pt),
  Tab / Shift+Tab go from field to field, Del deletes, Ctrl+D duplicates, Enter opens its properties, Esc lets go. The
  properties panel: name (dots group fields: "address.city"; names are checked so no two fields clash), tooltip,
  required, read-only, default value (or "checked/selected by default"), multi-line, most characters, format (number,
  currency, percent, three date styles, ZIP, phone, SSN: Acrobat's own AF scripts, which Inkvolt PDF runs too),
  choices (one per line, "Shown text = value" when they differ), the value a check box or radio button stands for (each
  radio button of a group its own), a push button's label and action (reset the form or
  print), text size (or auto), alignment, border and fill; plus Tab earlier / later (the order Tab fills them, shown as
  numbers with "Tab order"). **Detect Fields** looks at every page (in the background, with Cancel) for lines to write
  on, empty boxes, small squares, ☐ characters and runs of underscores ("Name: ______"), names each suggestion after
  the text beside it, and shows it dashed: Enter or Add field takes one, Del or Skip leaves it out, or Add all. Fields
  are real AcroForm fields with their own appearances (/DA, /DR fonts), so they show and fill in Acrobat, browsers and
  phones as well as here, without relying on NeedAppearances. Every change is one undo step; a signed file gets the
  change appended (with the usual warning), a protected one keeps its protection, and a hybrid XFA form loses its XFA
  part (asked first; XFA-only forms can't be prepared).
- **Edit Text & Images** (Edit menu or the command palette): change the page's own text and pictures. Text under the
  pointer shows a frame; a click opens an editor right over it, in its size, style and color, that says live how much
  wider or narrower the new text is (it doesn't reflow: wider text may run into what follows) and which characters the
  font can't draw. Enter (or clicking elsewhere) writes it in the text's own embedded font, Esc cancels. Only characters
  the font really holds can be typed (embedded fonts are usually subsets with just the characters the document used):
  any other is refused by name, never drawn in another font. Kerning outside the change is kept; a word space the font
  has no glyph for becomes a gap; new characters the font has but the PDF didn't use yet get their widths and their
  text (so copying and search still work). Pictures show a frame: click one to select it, drag to move it, drag a
  handle to resize it (Shift keeps its proportions), arrow keys nudge it (Shift: 10 pt), Delete removes it, Enter or
  Replace Picture… (or a double-click) puts another picture file in its box, upright and in its own proportions; other
  places that show the same picture don't change. Tab goes through the page's text and pictures (Enter edits the text).
  Each change is one undo step; a signed file gets it appended (with the usual warning), a protected one keeps its
  protection.
- **Images** (Review › Add Image… or the toolbar, I; Add Image from Clipboard): pick a picture (JPEG, PNG, BMP, GIF,
  TIFF; transparency kept) or take the copied one, then click where it goes; drag to move, drag the corner to resize,
  Delete removes it. A Stamp annotation with the picture as its appearance, so every viewer shows and prints it; listed
  in the Comments pane (picking it there selects it on the page). Each change is one undo step.
- **Links** (Review › Links, or the toolbar, N): drag a box over what should be a link (a click makes a line-sized one),
  then choose a web or email address (example.com becomes https://, name@example.com becomes mailto:) or a page of this
  document. With the Links tool the document's links show as dashed boxes: click one to select it, drag to move it, drag
  its corner to resize it, double-click or Enter to change where it leads, Delete removes it; with any tool, right-click
  a link for Edit Link… / Delete Link. **Link Selected Text…** (Review menu, right-click, Ctrl+K) makes the selected text
  a link without the mouse (one link over its lines). Addresses other than http, https and mailto ask before they are
  added (and, as for any link, before they are opened); script and data addresses are refused. International addresses
  are written the way PDF needs them (domain as punycode, the rest percent-encoded). Each change is one undo step.
- **Stamps** (Review › Stamp…, or the Stamp button; S puts down the last one again): Approved, Rejected, Draft, Final,
  Confidential, For Comment, Received, and "Approved by <you> on <date and time>" (your name from Settings,
  else your Windows user name), or custom stamps made from an image (a white background can turn transparent; up to 20
  saved on this PC, like the signatures). Click where it goes; drag to move, drag the corner to resize (redrawn sharp),
  Delete removes it. Real Stamp annotations with their own appearance (and the standard stamp names), so every viewer
  shows and prints them; listed in the Comments pane with their author; one undo step each.
- **Comments** (Review menu): highlight / underline / strike out selected text (Ctrl+Shift+H / U / X, or right-click),
  sticky notes (Ctrl+Shift+C), hover to read; the Comments pane lists them by page with replies, filter, edit and delete
  (undoable).
- **Draw** (Review › Draw, or the Draw button): pen (P), highlighter pen (M), rectangle (R), ellipse (E), line (L), arrow (W),
  text box (B: click to type a line, drag for a wrapped box) and callout (C: drag from what it points at to where its text
  goes). Live preview with mouse, pen or touch; Shift draws squares, circles and 45° lines; Esc goes back to the hand tool.
  With the hand tool, click a drawing to select it: drag to move, drag a handle to resize (a line's ends and a callout's
  tip move on their own), arrow keys nudge (Shift: 10 pt), Del deletes, double-click or Enter edits a text box. A
  floating style bar sets color (8 swatches or any color), line width, opacity, fill, border, text size and arrowheads;
  each tool remembers its last look. Every change is one undo step and shows in the Comments pane (picking one there
  selects it on the page). Works on turned views and turned pages; on a signed file it is an allowed change.
- **Attachments**: list, save, open attached PDFs in a tab, attach and remove files (never run by Inkvolt PDF). Saved
  attachments are marked as downloaded from the internet (Mark of the Web), like a browser download, so Windows and
  Office treat them with the same care.
- **Layers**: show/hide optional content for viewing and printing without changing the file; save as default.
- **Signatures**: verified in the background (digest, CMS signature, certificate trust with online revocation, a
  certificate meant for signing); the certificate is judged at the time of a timestamp from a trusted authority, else
  now (never at the signer's own clock). Changes made after signing are checked against what each signature allows
  (certification level, locked fields; page content, pages, layers and open actions never), so content swapped or hidden
  in a later update shows as invalid. An info bar and a details pane; a warning before an edit that would invalidate a
  signature. XFA-only forms get a notice.
- **Sign Digitally** (Review menu, the Sign button, or clicking an empty signature field): pick a digital ID from the
  Windows certificate store (smart cards and Windows Hello ask for their PIN), a .pfx file, or create a self-signed
  personal ID (RSA 3072, 5 years; optional password-protected .pfx backup); reason, location, a visible box (drag it on
  the page, with live preview and an optional handwritten image) or invisible; optional RFC 3161 timestamp (only a hash
  goes to the server; default DigiCert) and certification (first signature only). PAdES (ETSI.CAdES.detached, SHA-256,
  SHA-384/512 for EC P-384/P-521). The signature is appended as an incremental update, so earlier signatures stay valid,
  then saved as a new file (name-signed.pdf) and verified.
- **Redaction**: drag areas, mark selected text or every search match, then apply: the content is removed for good.
- **Sanitize Document** (Review menu, command palette): removes what a document carries besides its pages. The dialog
  counts what it found, one check box per kind (all on): metadata (document properties, XMP of the document, pages,
  images and fonts, comment authors and dates, article properties, other apps' private data; the file identifier is
  made new, so the copy can't be matched to the original); hidden layers with what they draw (cut out of the content, not just
  switched off), hidden comments and fields, comments, form field values, bookmarks, thumbnails; JavaScript (document
  scripts, open and additional actions of the document, pages, comments and fields, script actions of links, fields and
  bookmarks), Launch, Submit and Import actions, multimedia and XFA forms; links to web pages and other files; attached
  files (also associated files and portfolios); on a signed file, its signatures. The file is rewritten as a single
  version, so earlier versions kept by incremental saves and unused objects are gone too. Afterwards it says what was
  removed (the result is read back and scanned again; anything left is listed). A signed file's signatures no longer
  verify afterwards (the dialog says so); a protected file keeps its protection. One undo step.
- **Recognize Text (OCR)** (Review menu): scanned pages get an invisible text layer, so they can be searched, selected
  and copied; runs on the PC with Windows' own OCR, one undo step.
- **Export to Word, Excel or text** (File › Export, command palette): a page range, "recognize text on scanned pages",
  "open the file when done", progress with Cancel (nothing is written until the end). **Word (.docx)**: the pages are
  rebuilt as editable text: paragraphs (wrapped lines joined, hyphenated words rejoined), fonts, sizes, bold, italic and
  colors; headings (Heading 1-6, from type larger than the body text, so they show in Word's navigation pane);
  bulleted items as Word bullets, numbered ones keep their numbers; tables from ruled grids (merged cells, icons in
  cells) or from text lined up in columns; pictures inline, transparent ones kept transparent (a picture used again is
  stored once); charts and diagrams drawn with lines and shapes as a picture of the figure; two-column pages in
  reading order; a page whose text is turned sideways (a wide table set on its side) as a landscape page, and a few
  sideways lines (a margin stamp) as a paragraph; lines and logos repeated at the top or bottom of the pages become
  the header and footer, page numbers Word's own (not an item number beside the page's text); each page its own section
  with its size and orientation, its vertical spacing kept (the gap above each paragraph, taken in a little when the
  page would otherwise spill onto a second Word page). Forms: pieces of text side by side on a row (labels under a
  fill-in line, choices with their boxes) are one line with tab stops where they stood, and fill-in dots, rules or
  dashes are tabs with a dot, underline or dash leader up to where they ended; boxed tables keep their row heights (room
  to write in), boxes one under another stay separate tables, text in two cells set close together stays in its own
  cell, and a form's grid of boxes is a table, not a picture. Accents a typesetter draws as separate characters (TeX
  and older drivers) are joined to their letters ("Dirección", "ÁREAS"), and an accent standing alone whose shape is
  another sign (a font that names its "=" "dotaccent") is read as that sign. Fonts that aren't on the PC are listed
  with their kind (serif, sans serif, monospaced), so Word shows a like font in their place. **Excel
  (.xlsx)**: every table found (number columns set close together kept apart, a long table split into row groups kept
  as one, dot leaders dropped),
  one sheet per table named after its page, plain numbers as numbers, merged cells merged. **Plain text (.txt)**: the
  text in reading order, a paragraph per line, table rows tab-separated. Scanned pages without text are recognized
  with Windows' OCR first (on the PC); without an OCR language they are kept as pictures in Word. XPS, EPUB and the
  other formats Inkvolt PDF opens export too.
- **Reload** (F5) and an info bar when another program changes the open file. **Accessibility**: screen-reader names
  for pages, fields, links and lists; caret browsing (F7); F6 cycles command bar, pane and page (both panes of a split view); high-contrast aware.
- **Recovery copies**: every PDF with unsaved changes (edits, a combined or scanned document never saved) gets a copy in
  `%LOCALAPPDATA%\InkvoltPdf\recovery` at most every 20 seconds after a change, written in the background as Save would
  write it (a password-protected document stays protected), and at once when Windows signs out. A copy goes when its
  document is saved, undone back to its saved state or closed, and all of them on a normal exit. After a crash, a killed
  process or a power cut, the next start asks: **Restore** opens each document with its changes and back at its page
  (a protected one asks for its password; Save writes it to the file it came from, and a file changed meanwhile shows as
  changed on disk), **Discard**, or **Not now** (asked again next time). Each run keeps its copies in a folder of its own,
  locked while it runs (`RecoveryStore`). Settings › "Keep recovery copies of unsaved changes" turns it off.
- **Find** (Ctrl+F): floating find box with match case / whole words; Search pane (Ctrl+Shift+F) lists every hit.
- **Tools**: hand (H), select text (T, double/triple-click for word/line), snapshot to clipboard (G); links (asks
  before opening anything but http/https/mailto); Back/Forward (Alt+←/→).
- **Organize pages** (Ctrl+Shift+O): a grid of large pages; click / Ctrl / Shift to select, arrows to move, drag to
  reorder, Alt+Shift+arrows move the selected pages (announced to screen readers); the hovered or focused page shows
  rotate and delete buttons; double-click or Enter to open it, Esc when done. A bar under its header has the page actions
  with labels (rotate left and right, delete, duplicate, extract, move, insert from file, insert blank, crop; icons only when
  narrow), the same commands as the right-click menu.
- **Page edits** (all undoable; every edit shows a toast with Undo): rotate (Organize menu, toolbar or right-click; no
  default shortcut, since it changes the file), delete, insert from file or blank,
  extract (new tab, one file, or a file per page), split (by count, ranges, or bookmarks), move, duplicate, reverse,
  crop/uncrop, combine files. Drag thumbnails onto another tab to copy pages; drop PDFs onto thumbnails to insert them.
- **Compare Files** (File menu, start page, command palette): pick the original and the changed version (open tabs,
  the saved file behind a tab with unsaved changes, recent files or any PDF; Swap). The text of both is compared word by
  word over the whole document, so text that flows onto the next page isn't a change, and pages are lined up by the
  words they share: an inserted or removed page is one change (not a wall of words), a page rewritten in place is
  "changed". Rows of lined-up pages side by side with one scroll bar (both documents always scroll together);
  inserted words green, removed red, changed amber on both sides, with a marker where words went missing on the other
  side. A list of changes (click one, or a highlight on the page; F8 / Shift+F8 or Alt+Down / Alt+Up step through
  them) and a summary count. **Visual** (Ctrl+2) overlays the pages: ink only in the original red, only in the changed
  file blue, shared grey, with boxes around each area that differs: for drawings and scans. Pages without text (scans)
  say so instead of counting every word as changed; they are checked visually in the background and listed when they
  look different. Zoom with Ctrl+wheel, Ctrl+= / Ctrl+- / Ctrl+0 (fit). **Annotated Copy** opens a copy of the
  changed file with every text change as a comment (highlights quoting the old wording, notes where words or pages were
  removed, a summary note on page 1) in a new tab, to save and share; a signed file gets the comments appended, a
  protected one keeps its protection.
- **Command palette** (Ctrl+K): every command (with its icon), recent files, or a page number. **Shortcuts**: F1;
  tooltips show each button's shortcut. Error messages stay until dismissed; other notices fade.
- **Help › What's New** shows `WHATS-NEW.md` (embedded); after an update it opens once by itself with the versions since the one
  last run (`AppSettings.LastVersionSeen`; nothing on a new install or in dev-script runs). **Help › Report a Problem…** shows,
  then copies, the version, Windows, a settings summary and the log's last 200 lines, scrubbed of IP addresses, host names,
  UUIDs, serial-like IDs, file paths and the user's and PC's names (`InkvoltPrint.Core.Suite.Diagnostics`, shared with Inkvolt
  Print; tested there), and can open a new GitHub issue with the version filled in to paste them into. Nothing is sent by the app.
- **Settings** (Ctrl+,): *Reset to defaults* puts the dialog's choices back as a new install has them (saved with Save; recent
  files, signatures and the AI assistant's settings are kept).
- **Password protection** (File › Protect with Password…): an open password (with a strength hint) and/or a
  permissions password restricting printing (high/low resolution/none), copying, editing, comments, form filling and
  page assembly; AES-256 (or AES-128 for old readers). An undoable edit; save to keep it. Remove Protection… takes it
  off (asks for the permissions password if needed); Properties shows the protection. **Edits keep the protection**: a
  protected PDF stays protected after any edit, with the same permissions and passwords (RC4 files are upgraded to
  AES-128). For an AES-256 file opened with its permissions password, Inkvolt PDF asks once for the open password (or saves
  without one, if you say so); older files need nothing.
- **Reduce File Size…** (File menu): image quality (high 200 dpi / medium 150 / low 96 / keep), thumbnails, private
  app data, duplicate images and fonts, XMP metadata; runs in the background, then shows before/after sizes (one undo
  step; a file already compact is left alone).
- **Flatten…** (Organize menu): draws comments and/or form fields into the pages (optionally only what prints).
- **Header & footer** (Organize › Add Header & Footer…): text left, center and right above and below the page, with page
  numbers (`<<page>>`, `<<pages>>`), date and time (`<<date>>`, `<<time>>`, or a format: `<<date:yyyy-MM-dd>>`), the file
  name (`<<file>>`) and Bates numbers (`<<bates>>`: prefix, start, digits, suffix); font size, color, margins and a page
  range, with a live preview of the first page. Written into the pages (prints everywhere), placed on the page as shown
  (turned pages too); one undo step. Applying again replaces it on those pages; Remove Header & Footer takes off what
  Inkvolt PDF added (tagged in the file) and leaves the rest of the page alone.
- **Watermark** (Organize › Add Watermark…): a text (font size, color) or an image (width as a share of the page), at any
  angle (45° by default), see-through (10-100%), once in the middle or tiled across the page, over or behind the page's
  content; a page range and a live preview. Written into the pages like the header and footer, one undo step; applying
  again replaces it, Remove Watermark takes it off.
- **Measure** (Review › Measure, command palette): distance (click both ends), perimeter and area (click each corner;
  double-click or Enter finishes, Backspace takes a corner back, Esc cancels; Shift keeps a segment straight or at 45°),
  with the value shown by the pointer as you go. Each measurement is saved as a Line, PolyLine or Polygon comment
  labeled with its value (white-backed, upright as the page is shown), the value also its text, so it shows in every
  viewer and in the comment list; moved, reshaped or restyled, it is measured again. Values use the page's scale: Set
  Measuring Scale ("1 in = 10 ft", "1 cm = 2 m", decimals, this page or all) or Calibrate (click both ends of something
  whose real length you know, then type it) saves the scale in the document as a page viewport, the PDF's own way;
  scales a document already has (several per page for details) are used where they apply. Measurements and scales are
  written the way Acrobat writes them (/Measure /RL with number formats, /IT LineDimension, PolyLineDimension,
  PolygonDimension), so other viewers that measure read them; without a scale, values are real size (1 in = 1 in).
- **Save as PDF/A-2b** (File menu, command palette): an archival copy (ISO 19005-2, level B) of the document as it is
  now; the open document doesn't change. The copy gets an sRGB output intent (a profile Inkvolt PDF writes itself) and
  PDF/A metadata matching the document properties, loses what PDF/A forbids (password protection, which needs the
  permissions password; JavaScript and actions that run or hide things; multimedia; attached files; XFA; hidden comments;
  rollover appearances; picture smoothing; LZW compression; transfer functions), its comments and fields print and keep
  their look, and standard fonts that weren't embedded (Helvetica, Times, Courier, also named Arial, Times New Roman,
  Courier New) are embedded from Windows' metric-compatible fonts. When something can't be kept without changing the
  look (another font that isn't embedded, CMYK color without a profile, a digital signature, PostScript), nothing is
  saved and the reasons are listed. A summary says what was changed.
- **Batch** (File › Batch…, command palette): the same actions for many files. Add PDFs and images (Add Files, Add
  Folder with or without subfolders, or drag them in; images become PDFs first, on pages the size of the image, Letter or
  A4), then a list of actions in order: Reduce File Size, Protect with Password, Remove Password Protection, Sanitize,
  Add Watermark, Add Header, Footer & Bates Numbers (Bates numbers can continue from file to file), Rotate Pages,
  Flatten, Recognize Text (OCR), Export to Word, Excel or text, Export Pages as Images. Each action has the same
  settings as its own command. The results go to a folder with names from a template (`<<name>>`, `<<n>>` or
  `<<n:3>>`, `<<date>>`, `<<folder>>`), subfolders kept if you like; a name already taken gets a number ("report
  (2).pdf") unless you allow overwriting, and the originals are never replaced. Files run a few at a time on worker
  threads, as many as fit a memory budget (a very large file runs alone); each row shows its progress and result, a file
  that fails or is skipped says why and the batch goes on, Stop ends it (results already saved stay; nothing is written
  half). A file with a password asks for it when its turn comes (the open password, or the permissions password when a
  change needs it; Cancel skips that file, or skip them all) and keeps its protection; signed PDFs are left alone unless
  you choose to change them too (exports still read them). Double-click a row to open its result.
- **Print** (renders in the background, one sheet at a time; progress on the taskbar button, as for export, OCR and
  combine). Ctrl+P prints each page fit to the paper as last chosen. **Print with Options…** (Ctrl+Alt+P) adds **Page
  Sizing & Handling** after the printer is chosen (remembered, with a sketch of the first sheet and the sheet count):
  **Fit**, one page per sheet turned to the paper, at actual size (only pages larger than the paper
  shrink) or fit to paper (small pages grow too); **Multiple pages per sheet** (2, 4, 6, 9 or 16, across or down,
  optional page borders; the sheet is turned when that shows the pages larger); **Booklet** (saddle stitch: two pages
  per side, sheets ordered so the folded stack reads in order, padded with blank pages to a multiple of 4, binding on
  the left or right; set to print two-sided flipping on the short edge when the printer can, else it says so);
  **Poster** (each page enlarged 25-1000% across several sheets, overlap none to 1 in, optional cut marks at the middle
  of each overlap; sheets turned when that takes fewer). Export pages as PNG/JPEG, document
  properties (title/author/subject/keywords editable), password-protected PDFs. Also views XPS, EPUB, CBZ, FB2, images.
- **Scan** (File › Scan…, Organize › Insert from Scanner…): network scanners over eSCL (AirScan), using Inkvolt Print's
  code: the scanners Inkvolt Print remembers plus any found on the network; glass, feeder or both sides; color/grayscale;
  150/200/300 dpi; Letter/A4/Legal/whole area. Scan another page from the glass, or a whole stack from the feeder;
  Stop cancels the job on the scanner. The result opens as a new unsaved tab ("Scan yyyy-MM-dd HHmm.pdf") or goes into
  the current document at the chosen position as one undo step. Pages are the scanner's JPEGs as they are (no
  re-compression), with an invisible OCR text layer (on by default, as in Recognize Text).
- **Printer status when printing**: for a queue whose printer Inkvolt Print knows (matched by its queue association, the
  queue's device container, the address in its port, or its name), Inkvolt PDF shows the printer's state and toner after
  the Print dialog (ready, sleeping, …) and asks before printing to a printer that is offline or has an error (paper
  out, jam, door open…): Print anyway or Cancel. The check is read-only, cached briefly and given at most 2 seconds;
  without an answer, printing goes ahead.
- **Printer Settings (Inkvolt Print)** (File menu, shown when Inkvolt Print is installed) opens Inkvolt Print. Inkvolt Print's "Open in
  Inkvolt PDF" hands a saved scan to Inkvolt PDF (a running Inkvolt PDF opens it in a tab).
- **AI assistant (bring your own, off by default)** (Review › AI Assistant, command palette; right-click selected text ›
  Explain with AI): Inkvolt PDF has no AI of its own. In Settings › AI assistant you can connect one you choose: Ollama
  or LM Studio running on this PC (presets), or any OpenAI-compatible endpoint (`/v1/chat/completions`), on your network
  or a cloud service with your own API key. Pick the model from the endpoint's list (Test connection) or type it. The
  context (how much the model reads at once) is asked from Ollama before each use (`/api/ps` for the model as loaded,
  else its `num_ctx` from `/api/show`; 4,096, Ollama's usual default, when it can't tell; only the model's name is sent),
  and Ollama gets the answer's limit (`max_tokens`) so the prompt and the answer fit together: Ollama silently cuts a
  longer prompt, instructions first. For other endpoints set the context size as the server runs the model (LM Studio:
  Context Length when loading it; 4,096 by default). **Summarize** a page range (a long document is summarized in parts that
  fit the context, then combined; Stop cancels), **Ask about this document** in a pane at the right (follow-up
  questions keep the conversation; a Pages box limits what a question is about; when the pages don't fit, only the
  parts that share the most words with the question go), **Explain selection**. Answers stream in, are marked
  "AI-generated, may be wrong", have a Copy button, and their page citations ([p. 3]) are links to the pages.
  **What is sent, where**: before each send a window shows the destination (host and model, and in amber when the text
  leaves this PC), how much (characters, an estimate of tokens, the number of requests) and, expandable, exactly the
  text of every message. Only the text you asked about (with Ask, also the conversation's earlier questions and
  answers), the instructions and the model's name go: no file name, folder, document properties or other documents. A
  long summary's combining requests carry the model's own partial summaries: they are shown the same way before they go
  (always for an internet endpoint), and declining keeps the partial summaries as the answer. "Don't ask again for this endpoint" skips that window for one endpoint
  (undo it in Settings › AI assistant); the first send to an internet endpoint and text from a PDF that forbids copying
  are always asked about, whatever the endpoint. **Privacy**: off until you turn it on; nothing is sent until you confirm; requests go only to
  the endpoint you configure (no Inkvolt server, no default key, no telemetry; Bermudez Systems receives nothing). An
  endpoint on this PC (localhost) or your network (private addresses, `.local` names) keeps the text off the internet;
  any other host is labeled "Leaves this PC" and must use https://. That label is enforced when connecting: the name is
  resolved by Inkvolt PDF and only an address in its range (loopback, or private, link-local and unique-local ones) is
  connected to, so a name or DNS answer that leads elsewhere sends nothing. Host names must be plain ASCII (an
  international name in its xn-- form), so look-alike characters can't pass for another host. API keys are kept per endpoint in `ai-keys.dat`,
  encrypted with Windows DPAPI for your account (never in settings.json, never logged), and sent only to their endpoint.
  Requests to this PC or the network never use a proxy; redirects aren't followed. The log records only the host and
  sizes, never the text.

## Known limits

- Page edits go through PDFsharp, which rewrites the whole file, so its size can change. Signed PDFs are the
  exception: edits are appended as an incremental update, so signatures stay intact and show as "changed after
  signing". Redaction, page extraction and encrypted signed files still rewrite the file and break signatures
  (Inkvolt PDF warns first), as does any edit whose update can't be appended (Inkvolt PDF asks before committing it). Pages,
  comments and attachments removed from a signed file stay recoverable from its signed revision until the file is
  flattened (offered after such a removal; breaks the signatures). Revocation is checked only on request.
- Signing: no long-term validation data (no DSS/VRI, no embedded OCSP/CRL responses, no document timestamps), no
  field locks (FieldMDP), and DocMDP permissions of a certified file aren't enforced when verifying. Encrypted PDFs can't be
  signed (save an unprotected copy first). A self-signed ID shows as untrusted on other PCs until they trust it.
- Editing pages of a password-protected PDF needs its owner (permissions) password; opening it with the user
  password allows viewing, printing and copying only. Edits keep the protection; extracted and split pages are saved
  without it (Inkvolt PDF warns first). Non-ASCII passwords can't be typed to open a file (a MuPDFCore limitation).
- Read Aloud uses the voices Windows offers to apps (Settings › Time & language › Speech); Narrator's natural voices
  aren't available to apps. Text is read in the order the page stores it, so multi-column layouts can read across.
- Redacted pages become images (at 300 dpi). Their remaining text is put back by OCR as an invisible layer, so it
  stays searchable, but OCR text can contain recognition mistakes and the original fonts and structure are gone.
- OCR uses Windows' built-in recognizer: it needs an OCR language installed in Windows (your display language, else
  English), reads printed text only (not handwriting), and doesn't straighten skewed or sideways scans.
- Form scripts run in a sandbox (Jint: no network, files or other apps; time and memory limits) with Acrobat's form
  object model only: calculate, format, keystroke and validate events, document-level helpers, app.alert as a toast.
  Scripts that open URLs, submit, print or mail are ignored. XFA-only forms can't be filled.
- Right-to-left text with explicit bidi controls (embeddings, overrides, isolates) isn't laid out in new annotations,
  stamps and fields.
- Edit Text & Images is a first step: a piece of text is what the page draws with one text operator (often a line,
  sometimes a word or a single letter), edited on its own, with no reflow into the next line and no other font when
  the embedded one lacks a character (most embedded fonts are subsets). Text and pictures inside form XObjects (reused
  drawings, common in some generators and in stamped or flattened pages) are framed but can't be edited; nor can Type 3
  fonts, vertical text, CJK fonts with predefined CMaps, invisible OCR text, or text carrying ActualText. Simple CFF
  (Type 1C) fonts without a readable glyph list are checked against the PDF's widths and ToUnicode table only. A
  replaced or deleted picture stays recoverable from a signed file's earlier revision, as other removals do. Drawing: no polygon tool (existing polygons and polylines can be moved, resized and
  restyled), each pen stroke is its own annotation, and pen pressure is ignored.
- Prepare Form: one field selected at a time (no multi-select, align or distribute); no calculated fields, submit
  buttons, image buttons, comb or password fields to set up (fields that have them keep them, as do their own scripts
  and actions). New fields use Helvetica (other scripts get an embedded font when filled). A field shown in several
  places (same name) can't be made here, except radio buttons. Tab order follows the page's annotation order once
  changed; a page ordered by its structure tree is shown in annotation order. Detect Fields reads drawn lines, boxes and
  text: boxes with text in them, vertical rules, curves and scanned pages without OCR text find nothing; a table of
  empty cells becomes a field per cell.
- Compare: text is matched in the order the pages store it (multi-column layouts can show reordered text as changes),
  a paragraph moved elsewhere shows as removed in one place and inserted in another, and Thai, Lao or Khmer text (no
  spaces between words) is compared in long runs. Visual compare overlays pages at their top-left corners without
  aligning them, so two separate scans of the same paper, or a page shifted by a few points, look different all over.
  The annotated copy lists text changes only (visual differences aren't in it), and needs the permissions password of a
  protected changed file. PDFs only (not XPS or EPUB).
- Export to Word rebuilds the layout from what the pages draw, so it is a starting point for editing, not a copy:
  text flows in one column (multi-column pages become their columns one after another, not Word columns); text boxes,
  callouts and text over pictures become ordinary paragraphs where they fall; a paragraph split across pages or
  columns stays split; line spacing is Word's (single) and the space between paragraphs the PDF's, so a page set
  tighter than Word sets its font can still run onto a second page; text set wider in Word's stand-in font than in the
  PDF can pass the next tab stop on a form row; fonts are named as the PDF names them (a font not installed on the PC
  is substituted by Word, with a serif, sans serif or monospaced one as the PDF's was); headings are found by size only (bold
  body-size headings stay body text); bullets drawn as shapes rather than characters aren't recognized, and numbered
  lists keep their numbers as typed text; tables without lines need three or more rows lined up in columns, a cell
  wrapped over several lines can become extra rows, cells merged down a column are split, and two-column text with
  short lines can be taken for a table; a chart or diagram is found from many paths with little text around them, so a
  sparse drawing (a few arrows) keeps its labels as text and loses its lines, and a diagram whose labels sit in rows
  (boxes side by side) can still come out as text; turned pictures keep their own orientation; a hyphen at a line end
  before a lowercase word is dropped unless the document hyphenates with soft hyphens or both halves are words it
  uses elsewhere; several pictures side by side are stacked, and a picture covering the whole page behind text (a scan under
  its OCR text, a background) is left out; form fields export as their shown values; right-to-left text keeps
  MuPDF's order and isn't marked right-to-left. Running headers and footers need to repeat on at least half the pages
  (two at least) in the top or bottom tenth. On scanned pages only the recognized text is kept (the pictures on
  them are not cut out), sizes are estimated and fonts are Word's default. Excel gets only the tables; numbers with
  currency signs, percents or thousands separators other than "," stay text.
- Measure: straight segments only (no arcs, curves or counts), and rectilinear scales (not geospatial maps, whose
  measure dictionaries are left alone). Labels use Helvetica, so units are written plain ("sq ft", not ft²); a label
  sits by the line and isn't moved apart from it. A page's /UserUnit (very large drawings) is applied. A
  measurement made before the page was turned keeps its label's angle (as other comments do). Not tested in Acrobat
  itself: the dictionaries follow the PDF standard and Acrobat's own measurements.
- PDF/A: level 2b only (not 1, 3, or the accessible "a" level: no tagging is added). Fonts that aren't embedded are
  embedded only for the standard Latin faces, in their style (bold, italic), and only when the document's widths are
  that face's (other designs under a similar name, such as Helvetica Neue or condensed faces, refuse); Symbol and ZapfDingbats (often check marks in older forms), and other
  fonts, refuse the conversion, as do CMYK colors without a profile (the copy's output intent is sRGB) and signed
  documents. A form field without an appearance of its own refuses it too; comments without one are left out. Inkvolt
  PDF checks the rules it handles (Validate); it isn't a full validator: the copies made from the test documents (Word,
  Excel, PowerPoint and PDFsharp output, scans, comments, forms, standard fonts) pass veraPDF 1.30, but unusual files may
  not (font programs are not checked inside).
- PDF from Office files: needs Microsoft Office on the PC (any recent desktop version; not the web or Store-only
  apps); the PDF is what Office's own Save as PDF makes (Word adds bookmarks from headings and tags). Files protected
  with a password, and files that make Office stop to ask something (repair, a missing link), aren't converted (the
  first is refused, the second stops at the 3-minute limit). PowerPoint must be closed first. Excel prints each sheet's
  print area as Excel would. Not in batches. PDF from web pages: what Edge would print, so pages built for screens may
  break across pages oddly; content that loads only on scrolling or after a delay may be missing (the page is scrolled
  once); pages behind a login can't be reached (the session is private). Needs the WebView2 Runtime (Windows 11, or
  installed on Windows 10).
- Batch: printing isn't one of its actions (print a file from its tab); nor are page edits that need a page range or a
  choice per file (delete, extract, split, crop, insert). Actions run on every page of each file. Bates numbers that
  continue from file to file make the batch run one file at a time. A file is read whole into memory, and very large
  files run alone, so a batch of huge scans is slow rather than out of memory. XPS, EPUB and other formats aren't
  taken (PDFs and images only). An action list isn't saved between sessions (the folder and naming are).
- Split view: the second pane is for reading: comments, fields and drawings are edited, and search and find matches
  shown, in the main pane. One split per tab (two panes), not remembered when the tab is closed. Two different
  documents side by side: use Compare Files.
- Sanitize doesn't look for text drawn in white, under other content or outside the page (it can't be told reliably
  from text that shows), nor for hidden text in the structure tree's alternate text. Hidden-layer content that can't
  be cut out safely (a content stream that can't be decoded, or hidden text whose width the visible text right after it
  depends on) is kept with its layer, still hidden, and the report says so; so is a hidden layer named in a layer
  visibility expression (its content goes). An XFA-only form is kept (removing it would leave a placeholder page). Page
  labels, the structure tree (tags, alternate text) and the document's language stay. The result's XMP packet only
  names the program that wrote it.
- Scanning works with network scanners that speak eSCL (AirScan/Mopria); USB-only, WIA and TWAIN scanners aren't
  listed. Printer status needs the printer to be one Inkvolt Print remembers.
- AI assistant: answers are only as good as the model; small local models miss things and may invent them, so check
  the cited pages. Sizes are estimated cautiously (about 3 letters per token, a token for every digit, mark and CJK
  character; tables of figures cost far more than prose), with a 10% margin. Ollama's OpenAI-compatible endpoint takes no
  context size per request: to give a model more, set OLLAMA_CONTEXT_LENGTH or its context length in Ollama; a model
  not loaded yet is assumed to get 4,096 tokens. Scanned pages need Recognize Text first; pictures, charts
  and the look of the page aren't sent (text only). Answers show simple formatting (headings, bullets, bold); tables
  and code in an answer show as plain text. Ask picks the related parts of a long document by shared words, not by
  meaning. Endpoints are classified by the address as written (a public name that points to a private address still
  counts as the internet, with its https:// rule and amber label). Only OpenAI-compatible endpoints: providers with their own API (without an OpenAI-compatible
  one) need a local proxy such as LiteLLM.
